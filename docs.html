Install, use and build RUSH.

RUSH Office Suite is a local-first PDF and document workspace. This guide covers end-user installation, supported formats, developer setup and release packaging.

Install RUSH

Windows

For normal users, use the NSIS .exe installer. For schools, offices and managed fleets, use the .msi package. End users do not need Node.js, Python or CMake after the engines have been packaged.

RUSH-Office-Suite-2.1.0-x64.exe
RUSH-Office-Suite-2.1.0-x64.msi

The installer can create Start Menu/Desktop shortcuts and registers PDF, DOCX, ODT, RTF, TXT and legacy DOC file associations.

Linux and macOS

Linux release targets are AppImage and DEB; macOS targets are DMG and ZIP. Flatpak/Flathub publication is planned but must not be considered available until the official store listing exists.

Using RUSH

The sidebar can be collapsed with the menu button or Ctrl+B. Open a PDF to use page thumbnails, editing tools, OCR search, forms, protection and organization. Open or create a document for the Word-style editor with fonts, styles, lists, tables, images, links, emoji, find/replace and export to PDF.

Theme Studio includes RUSH, Leonore, Melody, Ephraim Royale, Minimal Notes and Midnight. The interface localization framework includes English, Spanish, German, Japanese, French, Portuguese, Russian, Italian, Chinese and Arabic. Arabic enables RTL direction.

Free and Pro

RUSH Free is intended to remain useful: PDF viewing/basic annotations, standard document creation/editing, organize/merge/split/rotate, basic conversion and local library features. RUSH Pro is planned as an affordable one-time upgrade for advanced OCR, redaction, certificate signing, premium themes/templates, version history, batch tools and optional local translation packs.

The public repository contains the verification architecture, not a private signing key. A production direct-sale license requires Nova Studio Plateformes to generate and securely keep the matching private key outside GitHub. Store builds can use store entitlement mechanisms instead.

Developer setup

Windows

git clone https://github.com/ephraimlifanjo/RUSH.git
cd RUSH\desktop
powershell -ExecutionPolicy Bypass -File .\scripts\setup-windows.ps1
npm run dev

For optional on-device translation runtime:

powershell -ExecutionPolicy Bypass -File .\scripts\setup-windows.ps1 -WithTranslation

OCR of scanned PDFs requires a local Tesseract runtime/language data. Normal selectable-text PDF search works without OCR.

Linux/macOS development

cd desktop
npm install
python3 -m venv .venv
. .venv/bin/activate
pip install -r python/requirements.txt
npm run build:ui
npm run dev

Build installers

Normal Windows builds do not need a .env. Environment variables are reserved for developer paths, signing credentials and store configuration; secrets must not be committed.

# Windows
npm run dist:win       # NSIS EXE
npm run dist:msi       # MSI
npm run dist:msix      # MSIX
npm run dist:portable  # portable EXE

# Linux
npm run dist:linux     # AppImage + DEB

# macOS (run on macOS)
npm run dist:mac       # DMG + ZIP

Before a public commercial release, use code-signing/notarization credentials on the release machine/CI secret store and generate the release integrity manifest.

Security model

The Electron renderer uses contextIsolation:true, nodeIntegration:false and sandbox:true. File-system access goes through narrow IPC methods. Public internet import accepts HTTPS only, blocks private/local DNS targets and limits supported content types and sizes.

Direct license files are signature-verified using a public key. Local version history uses SHA-256 snapshots. Secure packages use AES-256-GCM with a password-derived key. These controls raise the cost of tampering; RUSH does not make the dishonest claim that a desktop binary can be impossible to reverse engineer.

Certificate-based PDF signing is powered by a standards-oriented signing engine. Whether a signature meets a jurisdiction's legal requirements depends on the certificate, identity process and applicable law.

Current limits

Legacy DOC editing is conversion-based. Exact-layout translation of arbitrary PDF pages is not advertised: the optional local translation engine currently focuses on DOCX/TXT/RTF/HTML. Secure expiring web links require an online service; the no-backend RUSH build instead provides encrypted local secure packages with expiry metadata. Microsoft Store, Flathub and Uptodown buttons remain “Coming soon” until real listings exist.
