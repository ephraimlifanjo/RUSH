PRIVACY & SECURITY

Local files should stay local.

RUSH is designed so normal PDF and document work does not require an account or a dedicated RUSH cloud backend.

Local processingNetwork useHistoryLicensingApplication security

Local processing

PDF rendering, common PDF transformations, document editing, local indexing and OCR are designed to run on the user's computer when the corresponding local engine/runtime is installed. RUSH does not need document contents in a Nova Studio database to provide these functions.

Network use

The desktop app may open external store/help links at the user's request. The optional “Import HTTPS” feature downloads a file only from a public HTTPS URL selected by the user, rejects private/local network destinations after DNS resolution, validates content type and limits file size. Optional translation model packs may be downloaded separately when a user chooses to install them.

Version history

Local snapshots are stored in the application's local user-data directory. They are not automatically uploaded. Users or administrators should still maintain normal backups for critical institutional documents.

Licensing

The Free edition works without an account. Direct Pro license files are designed to contain signed entitlement data that the app verifies with a public key. The private signing key is not part of the public repository. Store editions may use the store's own purchase entitlement flow.

Application security

RUSH uses a sandboxed Electron renderer, context isolation, narrow IPC bridges, local file type/size validation, authenticated encryption for secure packages, public-key verification for direct license files and release integrity checks. Production releases should also be code-signed and notarized where supported.

No desktop application can truthfully promise to be “unhackable” or impossible to reverse engineer. RUSH's goal is to minimize exposed privileges, protect user data and make unauthorized modification detectable.
